    Where downloads come from

    Some hosts let a web page read their files and some do not, and the ones that do not cannot be talked round. Pick what does the fetching.

    Running yt-dlp on the machine you are sitting at is the shortest path: the video goes from the site straight to your disk, and nothing but this page comes from the internet. Browsers permit it because localhost counts as secure. On a phone this will not work — nothing is running on the phone. Use a deployed server there, or open your computer's own address in the phone's browser.

    YouTube turns anonymous downloads away with "Sign in to confirm you're not a bot". siphon already retries with several of YouTube's own clients, and that clears most of it. When it does not, your own session does — export cookies.txt with a Netscape-format cookie extension and upload it here.

    This is a logged-in session. Only upload it to a server you control, and use a throwaway account if you would rather not hand over your main one.

    The extractor runs in this page: it reads the link, picks a quality, downloads the stream and, when a file has to be merged or converted, loads ffmpeg.wasm to do it here. Nothing is uploaded and no link leaves the device.

    What it cannot do is argue with the browser. A host that sends no cross-origin headers — YouTube above all — is unreadable from a page, and no amount of JavaScript changes that. Those links need either your own server or a relay.

    A relay adds the missing header and forwards nothing else — no yt-dlp, no ffmpeg, no state, one file. relay/worker.js in this project deploys to a free Cloudflare Worker in about a minute. It is still a server, so it is optional and off until you fill this in; leave it empty and YouTube links simply say why they failed.

    A Piped instance's API answers a web page directly and proxies the media with the headers the browser needs — so YouTube works here with no relay and nothing of yours running. It is someone else's server: it sees every YouTube link you paste, instances come and go, and YouTube blocks them in waves. There is no default; bring an address you trust. When one is set it is tried first, and a relay is the fallback.
